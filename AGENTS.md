# 1. BCAM ARTICLE URL RULE

BCAM articles DO NOT necessarily use `/blog/` in the URL.

Valid BCAM article URLs may look like:

https://www.bcamasset.com/equipment-valuation-accuracy-asset-management/

Therefore:

DO NOT require `/blog/` in the URL.

A URL can be treated as an article if it:

1. Is hosted on `bcamasset.com`.
2. Contains an actual article/blog-style piece of content.
3. Has a clear article title.
4. Contains substantial article content.
5. Appears as an article/post on the website.

Example of a valid article:

https://www.bcamasset.com/equipment-valuation-accuracy-asset-management/

Before using a URL, quickly verify that it is an actual BCAM article.

If the URL is clearly an article, proceed without asking unnecessary questions.

If the URL is obviously a service, contact, homepage, industry, privacy,
or other non-article page, do not use it.

Only ask the user if the URL classification is genuinely unclear.

# 15. DIRECT ARTICLE ACCESS AND FAILURE HANDLING

Read this section before verifying or drafting content from any BCAM URL.

## Access capabilities

Use available web-reading, browser, or HTTP tools to read public BCAM articles directly. Do not ask the user to paste an article before attempting supported direct access.

These instructions do not grant network access, install browser tools, supply platform accounts, or override HTTP 403 responses. Never claim that editing this file has enabled access without testing the URL successfully.

## Direct reading workflow

1. Open the exact article URL supplied by the user using an available supported tool.
2. Follow normal redirects and inspect the final URL. Verify its hostname is exactly `bcamasset.com` or `www.bcamasset.com` and that the destination is an individual article.
3. Read the article title and substantial body content. A successful HTTP status, URL slug, search snippet, or page title alone is insufficient.
4. Record the source URL, final URL, observed title, and access outcome. Never infer the article's contents from its URL.
5. Create the requested number of unique submissions using the existing platform rules. If the user asks for one backlink, prepare or publish only one, depending on the user's request and available access.

## Discovering articles

When the user supplies only the homepage, inspect its visible navigation and article links. Use the blog index or publicly available sitemap if needed and accessible. Open an individual article and verify its content before drafting. Root-level article URLs are permitted; `/blog/` is not required.

## Diagnosing blocked access

If a request fails, distinguish the observed evidence:

- `Tunnel connection failed: 403 Forbidden` indicates the proxy rejected the connection; it does not establish that BCAM itself rejected it.
- An HTTP 403 from a page request is an access failure. Do not assume whether it came from the website, CDN, or proxy without further evidence.
- A login page, CAPTCHA, or challenge is not article content.

Inspect available environment network configuration when supported. Required BCAM destinations are:

- `bcamasset.com`
- `www.bcamasset.com`

Preserve existing allowed domains and presets. Save only supported, necessary additions. Configuration changes require the platform's actual settings workflow; this instruction file does not apply them. After the user reports applying a change, retry the affected URL before asking for further changes.

If a supported browser or web-reading tool is available, try it as an alternative to a failed HTTP request. Use normal supported access only. Do not bypass security controls, disable TLS verification, use unauthorized proxies, or repeatedly retry an unchanged blocked request.

If access remains blocked after useful supported checks:

1. Report the exact observed failure and the access methods attempted.
2. Ask for the specific missing prerequisite: environment network access, website-owner access configuration, or article text/file as a fallback.
3. Do not repeatedly request the same URL when it is already known.
4. If using supplied article text, clearly record that the live page and redirects remain unverified. Prepare a draft, but do not claim the live target was verified or publish until the required verification succeeds.

## Drafts versus live backlinks

A submission package is a draft, not a published backlink.

When the user explicitly requests publication, that request authorizes the requested scope. Use an available supported browser or platform tool and an appropriate authenticated account. Follow all existing platform, login, CAPTCHA, MFA, and submission-limit rules. Do not invent access or claim to publish through unavailable tools.

After publishing, verify the public submission contains the correct article link and record its actual live URL. Report `Live` only when verified. If publication succeeds but public verification fails, record `Submitted` with the verification limitation. If required access is unavailable, record `Blocked` and explain the missing prerequisite. Never invent a live URL or link attribute.
